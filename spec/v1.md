# Cercis 插件界面规范 v1

> 状态：草稿（可开始试用；编译器与渲染器在下一步实现）
> 适用范围：所有平台的插件界面（官方工具包与第三方插件）
> 一句话：**插件不画界面，只交一份"图样"；app 把同一份图样搭成各平台的原生界面。**

---

## 1. 为什么这样做

| 如果让插件各自画界面 | 换成这套规范之后 |
|---|---|
| 一个插件要写 Mac、Windows、Linux、手机好几套界面，写一次改五次 | 插件写一份，全平台通用 |
| 各平台长得不一样、字段顺序都可能不同 | 结构、字段、按钮动作一致，只有控件外观随平台 |
| 第三方插件想自己写原生界面时没有规矩 | 留了正规出口（见 §11），且不影响主流程 |

## 2. 不做什么（避免走偏）

- **不是**把任意网页翻译成原生界面——那等于重写一个浏览器，永远做不完。
- **不写业务逻辑**：图样里没有循环、没有计算、没有网络请求；一切逻辑都在插件自己的命令里。
- **不做精确排版**：打印、样品标签这类"毫米级"场景走 PDF / WebView 出口（§11 第 3 条）。

## 3. 三层结构与三个角色

```
HTML 稿  ──编译器──▶  图样（JSON）  ──渲染器──▶  各平台原生界面
  人写                   机器读                    用户看
```

| 角色 | 职责 | 不做什么 |
|---|---|---|
| 插件作者 | 写 HTML 稿、产出图样、提供命令 | 不画界面、不写样式 |
| app（宿主） | 渲染图样、管权限、降级、报错、选语言 | 不替插件写业务逻辑 |
| 内核 | 不认识界面，只转发"插件提供哪些界面" | 不参与渲染 |

## 4. 积木清单（v1 全部组件）

图样里只允许出现下面这些类型。**加新组件要走 §13 的流程**。

### 4.1 容器

| 类型 | 用途 | 关键字段 |
|---|---|---|
| `panel` | 一块有标题的区域 | `title`、`children` |
| `card` | 无边框分组 | `title`（可空）、`children` |
| `section` | 可折叠小节 | `title`、`collapsed`、`children` |
| `stack` | 顺序排列 | `direction`（`row`/`column`，默认 column）、`gap`（`none`/`small`/`medium`/`large`）、`children` |
| `split` | 左右（窄屏自动变上下）两栏 | `ratio`（0.1–0.9）、`children`（正好两个节点） |
| `grid` | 平铺网格 | `columns`（1–6）、`children` |
| `tabs` | 标签页 | `children`（每个是 `tab`） |
| `tab` | 一个标签页 | `label`、`children` |

### 4.2 展示

| 类型 | 用途 | 关键字段 |
|---|---|---|
| `text` | 文字 | `value`、`variant`（`heading`/`subheading`/`body`/`caption`/`code`） |
| `badge` | 小标签 | `value`、`tone` |
| `notice` | 提示条 | `value`、`tone` |
| `table` | 表格 | `columns`、`rowsFrom`、`emptyText` |
| `list` | 列表 | `itemsFrom`、`item`（每一项长什么样的模板）、`emptyText` |
| `keyvalue` | 字段名/值对照（详情区） | `items`（每项 `key` + `valueFrom`） |
| `image` | 图片 | `srcFrom` 或 `src`、`alt` |
| `progress` | 进度 | `valueFrom`、`max`（默认 100）、`label` |
| `divider` | 分隔线 | — |

### 4.3 输入

| 类型 | 用途 | 关键字段 |
|---|---|---|
| `form` | 表单容器 | `name`、`children` |
| `field` | 一个输入项 | `name`、`kind`、`label`、`required`、`placeholder`、`help`、`default`、`options` 或 `optionsFrom` |
| `file` | 选文件 | `name`、`label`、`accept`（如 `[".csv", ".tsv"]`）、`required` |

`field.kind` 允许：`text`、`number`、`date`、`textarea`、`select`、`checkbox`、`radio`。

### 4.4 动作

| 类型 | 用途 | 关键字段 |
|---|---|---|
| `button` | 触发插件命令 | `label`、`command`、`args`、`emphasis`、`confirm` |

## 5. 布局规则

- 只用 `stack` / `split` / `grid` + 权重表达布局；**不允许像素、绝对定位、自定义字体和颜色**。
- 间距、圆角、字号、控件外观**由各平台自己决定**（这正是"像本地应用"的来源）。
- **窄屏适配由宿主自动完成，插件不需要写两套**：

| 桌面 | 手机/窄屏（宿主自动） |
|---|---|
| `split` 左右分栏 | 改成上下堆叠 |
| `grid columns=3` | 最多 2 列 |
| `stack direction=row` | 放不下时自动换行 |
| 密度 `comfortable` | 密度 `compact` |

## 6. 文字与中英双语

任何文字字段都可以写两种形式：

```json
"label": "目标表"                                   // 中英同形
"label": { "zh": "目标表", "en": "Target table" }    // 双语
```

宿主按当前语言选择；缺英文时回落到中文。**插件不需要自己判断语言。**

## 7. 数据从哪来（三种绑定）

| 写法 | 含义 | 例子 |
|---|---|---|
| `$result.<路径>` | 上一次命令返回的 JSON | `$result.rows_imported`、`$result.findings` |
| `$form.<名字>` | 表单里当前填的值 | `$form.table`、`$form.file` |
| `$project.<字段>` | 当前项目的信息 | `$project.name`、`$project.template`、`$project.tables` |

补充规则：

- 文字里的 `{路径}` 占位符按 `$result` 解析：
  `"已导入 {rows_imported} 行"` → 实际显示 `已导入 12 行`。
- `optionsFrom`（下拉选项）可以指向 `$project.tables` 这类数组；数组元素写 `{value,label}` 或 `{name,label}` 都可以，宿主两种都认。
- 拿不到数据时**显示空状态文案**（`emptyText`），不要显示 `undefined`。

## 8. 什么时候显示（条件）

用结构化条件，不写表达式语言：

```json
{ "when": { "path": "$result.dry_run", "equals": true } }
{ "when": { "path": "$result.rows_imported", "exists": true } }
{ "when": [ {"path": "$form.table", "exists": true}, {"path": "$result.ok", "equals": true} ] }
```

可用判断：`equals`、`notEquals`、`exists`、`gt`、`lt`。数组表示"全部成立"。
默认（不写 `when`）= 一直显示。**不满足条件的组件不占位置**。

HTML 稿里用属性表达同一个条件（一对一映射，不引入表达式语言）：

```html
<cercis-notice tone="info" when-path="$result.dry_run" when-equals="true" value="试运行通过" />
<cercis-section title="列映射" when-path="$result.mapping">…</cercis-section>
```

- `when-path` 单独出现 = "这个值存在就显示"
- 还可以配 `when-equals` / `when-not-equals` / `when-gt` / `when-lt`
- 需要"多个条件同时成立"时，用 JSON 稿写数组形式（HTML 稿不支持，保持简单）

## 9. 命令怎么执行（含安全规则）

按钮被点击时，宿主执行：

```
<插件入口> <command> <args...> --project <项目目录> --json [--allow-write]
```

规则：

1. `args` 里的 `$form.x` / `$result.x` / `$project.x` 由宿主替换成实际值。
2. 必填项为空时，宿主**不发命令**，直接提示"请先填写 xxx"。
3. `--allow-write` 只在插件清单声明了写入权限、且已被信任时才由宿主附加——**插件无法自己要到写权限**。
4. 危险动作写 `confirm`（双语文案），宿主会先弹确认再执行。
5. "先试运行、再确认写入"这种两步流程，用**两个按钮**表达（第一个带 `--dry-run`），见 §12 例子。

## 10. 样式只给"意思"，不给"长相"

| 标记 | 取值 | 含义 |
|---|---|---|
| `tone` | `neutral` / `info` / `success` / `warn` / `error` | 语义色：宿主映射成各平台的颜色 |
| `emphasis` | `primary` / `secondary` / `danger` | 主次关系：主按钮 / 次按钮 / 危险按钮 |
| `gap` | `none` / `small` / `medium` / `large` | 间距档位 |

插件**不能**指定颜色、字号、像素、字体——这是"各平台像自己系统"的前提。

## 11. 三条路径（插件可选，按优先级）

| 路径 | 谁适合用 | 代价 | 声明方式（草案） |
|---|---|---|---|
| 1. **声明式**（推荐） | 官方插件全部；想省事的第三方 | 表现力有限 | `ui_tree: ui/import-csv.json` |
| 2. **平台原生片段** | 想要极致体验的第三方（如 macOS 用 Inspector） | 自己写 N 套，得逐个平台适配 | `ui_native: { macos: <入口标识> }` |
| 3. **WebView 保底** | 复杂图表、打印预览、已有网页界面 | 外观不随系统，性能一般 | `ui_webview: ui/complex.html` |

三条路径的共同规则：

- 在清单里声明**支持哪些形态**（`desktop-gui` / `tablet` / `phone`）；不支持的平台**自动隐藏入口**，不影响其他功能。
- 无论走哪条路径，**写入都必须经内核命令通道**，界面不能碰数据文件。
- 界面出错不能影响主界面：宿主隔离失败，并给出可读提示（安全模式下可整体禁用插件界面）。

## 12. 完整例子

见同目录 `examples/`：

- `import-csv.html` / `import-csv.json` —— 通用导入导出插件的"导入 CSV"向导（含试运行两步）
- `health-report.html` / `health-report.json` —— 通用体检插件的体检报告（汇总 + 明细表 + 空状态）

HTML 稿与图样是一一对应的：HTML 只是**给人写的写法**，编译后就是图样。

## 13. 版本与一致性

- 图样里必须写 `"spec": "cercis.ui/1"`；渲染器声明自己支持的版本。
- 加组件 = 小版本（1.1）；改字段含义、删组件 = 大版本（2），并给弃用期（与插件接口版本同一规则）。
- **一致性验收（黄金对照）**：同一份图样 + 同样的状态，各平台渲染器输出的"结构快照"必须**逐项相等**——快照只比较：组件类型与顺序、文字、可点击动作及其替换后的参数；**不比较**控件外观与像素。这样"结构一致、长相随平台"就有了可验证的标准。

## 14. 变更流程

1. 想加组件：先提 issue，附上**两个真实使用场景**；官方插件用不到的不加。
2. 规范先行：先改本文件与 `schema.json`，再改编译器，最后改各平台渲染器。
3. 渲染器必须通过一致性测试才能发布。
